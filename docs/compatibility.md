# Controller and game compatibility

The current editor writes ACE COMBAT 8 controller sections in `FlightStick.ini`. A valid section can be opened without the controller plugged in. A connected DirectInput device gives the editor its reported buttons, axes, and first POV hat. The game determines whether those inputs work in flight.

The included PXN drawing is original and groups the controls by physical location. The manufacturer manual provides the shape and layout reference. Use a photo you own or are allowed to use for a custom layout. The app keeps the photo path and marker coordinates on your PC.

Generic handling has been verified with synthetic multi-device files. The other models in the table have not been individually tested in this tool. Bring up Windows Game Controllers with `joy.cpl` to verify numbering if the manual and driver mode disagree. If the game creates no profile, try the manufacturer's PC or Flight mode and re-open the game. A device exposed only as an XInput gamepad may have no editable section here. Additional native POV hats, force feedback, and two devices sharing one indistinguishable product ID are outside current support. PXN's labeled POV2 works because it reports as buttons 17–20.

## Multiple bindings and held actions

`inputSettings` is an array. The editor adds or removes one entry at a time, preserves other entries and their modifiers, and keeps assignments independent per device. Saving the array is verified. How many alternatives a specific in-game device profile consumes still needs an in-game check.

The current configuration exposes `Target` and `SpecialRight`. It does not expose separate target-look or cutscene-skip bindings to this editor. An extra button mapped to `Target` inherits both its tap and hold behavior. A dedicated hold-only button would require a separately exposed game action or a runtime input mapper with game-specific behavior. The project currently uses the game's configuration file.

[AC8HOTAS documents native profile slots and multiple inputs](https://github.com/Drumsmasher17/AC8HOTAS). Its runtime mod and slot behavior are separate from this file editor.

## Other games

| Candidate | Feasibility | What an adapter needs |
| --- | --- | --- |
| ACE COMBAT 7 | The closest next target, with similar actions and a different `Input.ini` grammar. | Collect real profiles, confirm per-device syntax for multiple inputs, and test read/write/reload against the game. [Publisher's Steam flight-stick update](https://store.steampowered.com/news/posts/?appids=502500&enddate=1559148156&feed=steam_community_announcements) |
| Elite Dangerous | A good file-based candidate. Frontier documents backing up and restoring custom bindings. | Read the versioned `.binds` format, retain device identifiers and preset names, preserve simultaneous modifiers and all unedited settings. [Frontier support](https://customersupport.frontier.co.uk/hc/en-us/articles/25580471182620-Back-up-your-game-settings-and-keybinds) |
| DCS World | Feasible per aircraft and per controller. More work than a single global profile. | Read per-aircraft profile differences safely as data, account for default bindings, and validate with the game's save/load workflow. [Eagle Dynamics configuration FAQ](https://www.digitalcombatsimulator.com/en/support/faq/501/) |
| Microsoft Flight Simulator | Supports device presets and in-game editing. Direct file integration needs more investigation. | Confirm an officially supported export/import format for the target version before enabling writes. [Microsoft Flight Simulator control settings](https://flightsimulator.zendesk.com/hc/en-us/articles/360016018600-Peripheral-Control-Settings-Overview-and-FAQ) |

Reuse the physical input selector, per-device photos, action badges, localization, and change preview. Keep parser, serializer, path discovery, input constraints, and action names per game. The quickest proof of concept is a read-only ACE COMBAT 7 import with real samples, followed by editing a copied configuration and testing it in game.
